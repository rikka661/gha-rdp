# GitHub Actions 临时远程桌面（走 Tailscale，不用 ngrok）

一句话：**花几分钟，在 GitHub 的机器上开一台带国外网络的 Windows 电脑，用远程桌面连进去操作。**

先把话说在前面，这机器有仨硬限制，不是我没做好，是平台规矩：

| 限制 | 具体 |
|---|---|
| **最多 6 小时** | GitHub 官方硬顶，job 到点强制终止，改 `timeout-minutes` 也没用 |
| **什么都不保留** | 会话一结束整台机器被销毁。桌面里的文件、浏览器记录、登录状态，全部消失 |
| **每次都是新 IP** | 出口是 Azure 机房的 7036 个网段随机取，网站每次都可能让你重新验证 |

所以它适合「偶尔借一台境外机器办一件事」，**不适合当日常上网的代理**。真要日常用，走 Cloudflare 节点那条路（本机已有 `cf-node` 技能）。

这个目录里有**两套**东西，各管一件事：

| 文件 | 是什么 | 要准备什么 |
|---|---|---|
| **`.github/workflows/proxy.yml`** | **就想要一个代理，用这个**。跑起来是个 VLESS 节点，粘进 Clash Verge 就能用 | **什么都不用**。不要 Tailscale、不要 Secrets、不要信用卡 |
| `.github/workflows/rdp.yml` + `scripts/` | 一台带远程桌面的境外 Windows，偶尔借来办一件事 | 要注册 Tailscale + 设 2 个 Secrets（下面第一节起讲的就是它） |

---

## 零、最省事那条：`proxy.yml`（零注册、零配置）

### 你要做的，一共三步

1. **建一个仓库**，把 `proxy.yml` 放进 `.github/workflows/` 里（保持这个路径，名字随意）。
   - **建议用私有仓**：这个工作流会把节点地址打在日志里，公开仓的日志全世界能看 —— 谁看到谁就能在你这台节点上跑流量。私有仓日志不外泄。
   - 「公开仓不限分钟」在这里不是刚需：Linux runner 是 1 倍计费，GitHub Free 私有仓每月 2,000 分钟 ≈ **每次开 2 小时、一个月能开 11 次**，个人够用。真要不限分钟再考虑公开仓。
   - 账号还是建议用小号，理由见第四节。
2. **仓库的 Actions 页** → 左侧选 `简易代理（零注册、零 Secrets）` → **Run workflow** → 时长**第一次选 30 分钟** → 点绿色 Run workflow。
3. 约 1 分钟后**点进这次的日志**，翻到「拿这个去用」那段，复制那行 `vless://...`，粘进 Clash Verge 的「导入」里。完事。

### 它为什么长这样（一句话）

runner 没有公网 IP、外部连不进去，这是 GitHub 的架构死结，**任何办法都省不掉这一层**。所以这里让 runner **主动往外**连 Cloudflare 的快速隧道，把本地 7890 端口接出去；快速隧道不用注册账号，代价是域名每次随机变。

### 这个版本要知道的四件事

1. **最多 6 小时**，到点节点自动作废，不能续 —— 想「一直开着」得写自触发循环，而那正好是最容易触发账号处理的行为，我刻意没做。
2. **每次地址都不一样**，用完这次就没了。别收藏，每次重新点 Run。
3. **UUID 和路径每次新生成**，机器一销毁就作废，不落盘也不复用。
4. **`vless://` 链接 Clash Verge 新版能直接粘**；万一它不认，用 v2rayN（Windows）或 NekoBox（安卓）粘同一行，或者按日志里那份「手动填参数」自己填 —— 我也可以给你生成一份 mihomo 的 YAML 配置。

### 验证状态（说实话）

YAML 和三个 bash 步骤的语法都过了（`bash -n`），但 **xray 与快速隧道之间的实际握手，只有真跑一次才知道**。所以第一次请选 30 分钟、盯着日志：

- 卡在「xray 没起来」→ 把它的日志发我（配置字段跟 xray 版本有关，可能要改）
- 卡在「60 秒没等到隧道地址」→ 是 cloudflared 那边，日志也会打出来
- 有地址但 Clash 连不上 → 先试「手动填参数」那几项，确认 `传输=ws`、`TLS=开`、路径前面有斜杠

## 一、你要自己做的三件事（只有你本人能做）

### 1. 建一个 GitHub 小号，用它 —— 这是最重要的一条风险规避

这套玩法命中 GitHub 条款里「带宽明显超额」那一条（AUP §9，原文允许 GitHub 暂停账号），而且**它封的是账号，不是仓库**。

**别用你主力账号跑这个。** 注册一个新的 GitHub 账号专门干这事，被封不心疼。你主力账号上挂着 AE 桥接、Blender 桥接、GitHub 网盘那些真项目，不值得为这个赌。

流程跟「用公共仓」不冲突：小号上新建仓库 → 仓库类型选 **Public**（公开仓不限分钟数）→ 把本目录的文件推上去 / 或者在网页上逐个新建文件粘贴内容。

> 用公开仓有个必须知道的前提：**公开仓的 Actions 日志全世界都能看**。所以这份实现里没有任何一步会打印你的口令或 key，脚本里凡是可能回显的地方都过了 `Protect()` 遮罩一遍。我参考的那个印尼项目（`xykal/XyRDP`）恰恰是把口令 base64 编码后打印、专门绕过 GitHub 的 `***` 遮罩 —— 公开仓上这么干等于把口令贴给全世界，我没有照抄。

### 2. 注册 Tailscale，生成一个 auth key

到 <https://login.tailscale.com/start> 注册（免费档：6 个用户、设备数不限量、页面上没写要信用卡）。

然后进 **Keys** 页面 → **Add another...** 生成 auth key：

- **选 Reusable，别勾 Ephemeral。** 反直觉但很关键：Tailscale 免费档的定价页上写着「**1,000 mins per month for ephemeral resources**」—— 一次性节点是**按分钟计量**的，1000 分钟约等于每月 16 小时，而我们这套每跑一次就是一台新节点、天生就该算 ephemeral，正好撞在这个额度上，超了就连不进你的网了。所以用普通 Reusable key，节点残留交给收尾脚本删（下面第 3 步的 `TS_API_TOKEN`，或者你自己在网页上删，都不影响能不能连）。
- 有效期**选 30 天，别选永久**。这东西躺在公开仓的 Secrets 里，到期自动作废比一直有效安全。
- **别选 One-shot**：一次性 key 用完就废，每次会话都得回网页重新生成。

生成的 `tskey-auth-...` 就是 `TS_AUTHKEY` 的值。

**Tailscale 在这里起的作用**：runner 没有公网 IP、外面连不进去（这是整个方案最硬的那道墙）。Tailscale 是 runner **主动往外连**、注册进你的私有网，然后拿到一个 `100.x.x.x` 地址，你在自己设备上按这个地址连 —— 全程不经过任何第三方中继，所以：**地址和口令不需要出现在日志里**，而且**只有你 tailnet 里的设备能碰那台机器的 3389**（ngrok 那条路是把它捅到公网让人撞口令）。

### 3. 在仓库里设 Secrets

仓库 **Settings → Secrets and variables → Actions → New repository secret**，加这几个：

| 名字 | 必填 | 值 |
|---|---|---|
| `RDP_PASSWORD` | 必填 | 你自己想的远程桌面口令。至少 8 位，含大小写字母和数字，**别跟你在别处用过的重复** |
| `TS_AUTHKEY` | 必填 | 上面生成的 `tskey-auth-...` |
| `TS_API_TOKEN` | 选填 | 管理页 Admin → Keys → API tokens 生成，角色选 Operator 即可。设了它，会话结束时脚本会自动把这台设备从你的设备列表删掉；不设也能用，只是列表会越堆越长 |

## 二、开 / 连 / 关

**开**：仓库 **Actions** 标签 → 左边选 `RDP 临时远程桌面` → **Run workflow** → 下拉框：

- `duration_minutes` 选 **25**（第一次跑强烈建议选最短这个，先验证能连上再考虑加长）
- `device_name` 默认 `gha-rdp` 就行
- 点绿色 **Run workflow**

大约 2~4 分钟准备完（装系统组件 + 装 Tailscale），然后进 **这个 workflow 的运行日志**，翻到「本机接入结果」那一段，会看到：

```
私有网 IP       : 100.xx.xx.xx
MagicDNS 域名   : gha-rdp.your-tailnet.ts.net
用户名          : aideck
本地怎么连：开始菜单搜 mstsc → 计算机填 100.xx.xx.xx → 用户名 aideck
```

**连**：本机装 Tailscale 客户端（Windows Store 或官网下），**登你自己那个 tailnet 账号**，然后 `Win+R` → `mstsc` → 计算机填那个 `100.x` 地址（或 MagicDNS 域名）→ 用户名 `aideck` → 口令填你设 `RDP_PASSWORD` 时那串。

**关**：等它自己到点，或者到 Actions 页面点 **Cancel workflow**（提前收工，收尾脚本带 `if: always()`，取消也会执行退网删除）。

### 一个你大概会踩的坑

**本机的 Clash Verge 如果开着 TUN 模式，会把 Tailscale 的路由抢掉，表现是 mstsc 连 `100.x` 一直超时。** 处理办法：连 RDP 这段时间临时把 Verge 切到「规则/不使用 TUN」，或者直接停 Tailscale 之前的 Clash 服务。这条跟代码无关，是两台虚拟网卡在抢默认路由。

## 三、我做了哪些规避，以及你必须配合的部分

### 代码里已经兜住的

| 设计 | 挡的是什么 |
|---|---|
| **只留 `workflow_dispatch` 手动触发**，没有任何 `push`/`schedule`/`pull_request`/自循环保活 | `pull_request` 是公开仓泄 Secrets 的头号路子；自循环保活正是「用自动化手段给服务器造成不当负担」的典型特征（AUP §4） |
| **`concurrency` 只允许一个会话同时跑** | 那个项目的作者自己总结的守则里有一条「一小时别用同一个账号开 5 个以上 RDP 仓库」，这条我写死在配置里了 |
| **默认 25 分钟、上限 350 分钟**，跑满自动退出 | 让它结构上不可能变成一台常驻转发服务器 —— 而 §9 判的就是「相对同类用户明显超额的带宽」 |
| **不打印任何口令/key**，所有可能回显处过 `Protect()` | 公开仓日志全世界可读 |
| **保留 NLA（网络级身份验证）** | 这台机器对「整个互联网」可见（虽然只有 tailnet 内可达），NLA 能在进桌面前就挡住爆破 |
| **收尾自动 `logout` + `down` + API 删设备** | 不在你的私有网里堆僵尸节点 |
| **`permissions: contents: read`** | 万一被人塞了个恶意 action 进来，它拿不到写权限 |

### 必须你自己遵守的（代码管不到的部分）

1. **别在里面登录任何你真正在用的账号。** 这台机器不是你的 —— GitHub 和 Azure 在主机层面技术上看得见里面的一切。要注册东西就用一次性邮箱、临时账号。输过的密码，用完当它已经泄露。
2. **别下载大文件、别看视频。** 流量特征是「超额带宽」最直接的判定依据，也是封号最快的路子。当远程浏览器用，够用就行。
3. **手动触发、用完就停**，别挂一整天，别搞多仓库并发。
4. **`RDP_PASSWORD` 用一次性口令**，跟其它地方不重复。
5. **小号跑。** 这条重复第五遍了，因为它是最值钱的一条。

## 四、连不上怎么查

按顺序，别跳：

1. **日志里「检查 Secrets 是否就位」这一步红了吗** → 名字拼错或没设，错误信息会直接告诉你缺哪个。
2. **「本机接入结果」里 `私有网 IP` 是不是「没拿到」** → key 的问题：是 one-shot 已用掉、还是 ACL 拦了、还是设备数超了。日志最后会贴 `tailscale status --json` 原文，看 `Self` 段。
3. **有 IP 但 mstsc 超时** → 九成是上面那条 Clash Verge TUN 抢路由；其次是本机 Tailscale 没连上或登的不是同一个 tailnet 账号。
4. **连上了但口令不对** → 看「远程桌面准备情况」那一段，确认 `账号 aideck 已创建`、`组成员 Remote Desktop Users 已加入`、`TCP 3389 监听 有`。
5. **整台机器起不来** → `windows-2022` 镜像偶尔会排队很久，换个时间再跑。

**注意**：Windows runner 上的行为我没法在本地验证 —— 第一次跑请选 25 分钟，全程盯着日志，哪一步红了把那一步的输出发给我，我来改。这份东西第一次跑通需要来回调的概率不低，这是实话。
